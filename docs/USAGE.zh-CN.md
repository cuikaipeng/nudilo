# 日常使用

[English](USAGE.md) · [简体中文](USAGE.zh-CN.md) · [README](../README.zh-CN.md)

## 完成首次配置

概览提供三步引导：检测 AI 助手、绑定通知渠道、接收测试通知。默认只显示已检测到、
使用过或手动添加的助手；「添加助手」可以显示其他支持的助手。只使用 Codex 或
Claude Code 中的一个即可。

三个步骤都有完成依据后，引导会自动收起。「稍后」可以隐藏引导，在「设置 →
显示配置引导」中可以重新打开。渠道测试成功只能验证发送环节，仍应在助手中完成
一次真实会话，检查事件能否被采集。平台接收成功不代表手机一定弹出了通知，手机
提醒权限见[各平台配置指南](CHANNELS.zh-CN.md)。

## 判断提醒是否正常

概览和侧边栏使用相同的整体状态。只要有可用助手和已保存的渠道，其他渠道异常时
仍可继续工作；未使用的助手不会影响整体就绪状态。最近的真实事件显示在渠道卡片
上方，点击「查看全部」进入完整通知记录。渠道卡片统一显示 Logo、名称和配置状态，
鼠标悬停在已配置的卡片上可查看最近发送状态。

打开已配置渠道，可以看到接收位置、最近发送状态，以及真实 AI 事件是否已送达平台。
测试消息与真实事件分别标记。「配置详情」展开已保存凭据的摘要；「编辑配置」打开
自动填入的原有内容，密钥继续遮挡。「发送测试」只发到当前渠道，不受项目规则和
暂停状态限制。「移除渠道」会先要求确认。

发送状态依据当前配置下保留的通知记录。再次保存配置会重置这些依据；清空通知记录
也会清除发送依据。「尚未测试」代表没有保留的成功发送记录，不代表配置一定无效。

「概览 → 诊断连接」检查助手监听器、本地事件队列和已保存凭据，一个环节失败后会
继续检查其他环节。诊断不会发消息、启动模型会话、修复监听器或访问 IM 平台接口。
「助手设置」打开对应的关联控制，「重新关联」用于修复监听配置；「测试渠道」
打开渠道页面，由你明确点击发送测试。网络和平台权限是否正常，需要通过测试消息
或真实事件验证。诊断结果反映最近一次检查；修复本地存储问题后，再次诊断可刷新相关提示。

## 暂停一段时间

点击概览中「暂停提醒」右侧的下拉箭头（「暂停时长」），或在菜单栏/托盘中选择
「暂停」，可选 15 分钟、
1 小时、明天上午 09:00 或直到手动恢复。「明天」按选择时电脑的本地时间计算。
直接点击「暂停提醒」会无限期暂停，「开启提醒」可以提前恢复。概览和托盘菜单会
显示当前恢复时间。

恢复时间会保存。Nudilo 运行时到点自动恢复；如果电脑睡眠或软件已退出，则在下次
唤醒或运行后恢复。记录的暂停时段内产生的事件会跳过，唤醒后才读到队列里的事件
也不会补发。同一次运行中，暂停前已经等待发送的记录会暂存，恢复后仍遵循
24 小时过期规则；退出后重新启动则会跳过这些旧的待发送记录。
已经开始的发送可能完成。暂停时仍可主动发送渠道测试。

## 关闭窗口与退出软件

关闭窗口后，Nudilo 继续在菜单栏／系统托盘运行，通知照常发送。选择「退出 Nudilo」
才会结束程序。下次启动时，启动前产生的提醒，以及上次留下的待发送、待重试记录，
会在通知记录中标为「已跳过」并说明原因，不会自动补发到手机。启动后产生的新提醒
正常发送。重启安装更新时也遵循这个规则。
如果只是电脑睡眠、软件仍在运行，唤醒后继续遵循原有的重试、暂停和 24 小时过期规则。

## 不同项目使用不同渠道

这是可选设置；没有规则时，新通知会发送到所有已配置渠道。

1. 先配置并测试需要使用的渠道。
2. 打开「设置」，向下滚动到「项目分流」。
3. 展开「按项目选择渠道」，点击「添加规则」。
4. 填写通知记录中显示的完整项目名称，或点击「选择最近项目」。
5. 选择全部助手、Codex 或 Claude Code，并勾选一个或多个已配置渠道。
6. 点击「保存规则」。

项目名称精确匹配，区分大小写。使用通知中已有的文件夹名称，不采集完整路径。
不同目录下的同名项目会共用规则。指定助手的规则优先于同项目的「全部助手」规则，
相同项目和助手组合不能重复添加。

命中规则后不会自动改发到其他渠道。目标渠道被移除或不可用时，规则会保留并提示
处理，相关通知会被跳过或记录发送错误；规则里其他正常渠道仍可收到。编辑规则即可
修改接收渠道。

修改规则不会把旧通知转发到新勾选的渠道；不再符合规则的旧待发送项会在处理时跳过。
移除规则需确认，之后的新事件会使用其他匹配规则；没有匹配规则时，恢复为发送到
所有已配置渠道。渠道测试始终只发到当前测试的渠道。每个平台仍只有一个活动接收目标。

## 查找一条通知

通知记录按本地日期分组。可以搜索项目名（不区分大小写，支持部分名称），并同时按
助手和发送状态筛选。状态筛选也会匹配一条多渠道通知中的单个渠道；选择具体助手后，
不显示渠道测试消息。

展开「发送详情」查看渠道错误、下次重试时间或跳过原因。真实事件发送失败后可以
「重试失败的渠道」，成功渠道不会重复发送同一事件。初始显示最多 100 条匹配记录，
点击「显示更多」查看其余保留记录。

「清空全部」需确认，会清除可见发送依据并取消待重试项，同时保留少量事件标识，
防止旧事件重新通知。保留规则详见英文[行为与数据说明](BEHAVIOR.md)。

## 使用设置

打开设置后，上下滚动可查看通用、通知类型、通知内容、项目分流、各助手、外观和更新。
侧边栏更新提示以及托盘中的更新操作会直接定位到更新设置。

可以使用 Tab / Shift+Tab 切换控件，空格切换开关，回车执行操作；菜单和选择框支持
方向键，Esc 关闭弹出菜单。原生框架能读取到系统偏好时，界面会应用系统文字缩放、
高对比度和减少动态效果设置。引导、诊断、分流、暂停选项和筛选均提供中英文。
发送到 IM 的消息仍跟随软件语言或软件解析到的系统语言。
